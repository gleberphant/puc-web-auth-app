1. Visão geral

O projeto é uma aplicação web composta por um backend, que oferece uma API REST para gerenciamento de usuários, e um frontend, que permite demonstrar e utilizar os recursos da API.

A solução aplica conceitos de APIs REST, Web Services, autenticação, autorização, controle de acesso e segurança de aplicações web.

Funcionalidades

  • Cadastro, consulta, atualização e exclusão de usuários.
  • Login com validação de e-mail e senha.
  • Geração e validação de token JWT.
  • Controle de acesso por perfil de usuário.

3. Segurança com JWT

O frontend verifica se existe um token salvo no localStorage. Quando não existe, exibe a tela de login. As credenciais são enviadas em JSON para POST /login, sem serem colocadas na URL.

O backend valida o usuário e a senha, cria um JWT assinado com uma chave secreta e devolve o token ao cliente. O middleware verifica a assinatura e os dados do token antes de liberar rotas protegidas.

Informações do token

  • uid: identificador do usuário.
  • login: e-mail ou login do usuário.
  • perfil: nível de acesso.
  • iat: data de emissão.
  • exp: data de expiração.

A validade definida é de uma hora, equilibrando segurança e praticidade. Em uma evolução do projeto, a chave deve ficar em variável de ambiente e pode ser adotado um fluxo com refresh token.

4. Controle de acesso (RBAC)

Os endpoints devem respeitar o perfil do usuário autenticado:

  • Administrador: acesso total para criar, consultar, editar e excluir usuários.
  • Operador: pode consultar usuários e atualizar informações.
  • Cliente: pode visualizar apenas os próprios dados.

A autorização deve ser aplicada nas rotas protegidas; possuir um token válido não significa ter permissão para todas as operações.

Mapa de permissões

Rota Método Perfis
/usuarios GET admin, usuario
/usuarios POST admin
/usuarios PUT admin
/usuarios DELETE admin
/login GET admin, usuario, cliente
/login POST admin, usuario, cliente
/login PUT admin, usuario, cliente
/login DELETE admin, usuario, cliente

5. OAuth 2.0

Uma aplicação parceira poderia acessar a API por meio do fluxo Authorization Code. A aplicação não recebe nem precisa armazenar a senha do usuário.

O usuário seria redirecionado para o servidor de autorização, faria login, analisaria as permissões e autorizaria ou recusaria o acesso. Depois, a aplicação parceira receberia um código temporário e o trocaria por um token de acesso usando uma comunicação segura.

O acesso deve usar escopos. Por exemplo, uma aplicação pode receber permissão somente para consultar os dados do usuário, sem poder editar ou excluir registros.

Para acessar um endpoint protegido, a aplicação envia o token no cabeçalho Authorization usando o esquema Bearer: Authorization: Bearer <token_de_acesso>. A API valida assinatura, validade e escopos antes de liberar o recurso.

  • A senha não é compartilhada com a aplicação parceira.
  • O usuário delega apenas as permissões necessárias.
  • O acesso pode ser revogado sem alterar a senha principal.
  • Tokens de curta duração reduzem o impacto de vazamentos.
  • O protocolo facilita integrações padronizadas.

O OAuth 2.0 é apresentado como conceito e não está implementado neste projeto.

6. Análise de segurança

Risco Mitigação
Senhas armazenadas ou comparadas em texto puro Armazenar somente hashes seguros, como bcrypt ou Argon2, e nunca salvar a senha original.
Roubo ou interceptação do token JWT Utilizar HTTPS, validade curta, validação de assinatura e expiração e armazenamento seguro no frontend.
Exposição ou comprometimento da chave secreta do JWT Manter a chave em variável de ambiente ou serviço de secrets, usando um valor longo e aleatório.
Ataques de força bruta contra o endpoint de login Aplicar limitação de tentativas, atrasos progressivos e bloqueio temporário quando necessário.
Acesso indevido a recursos de outros usuários Aplicar RBAC em cada endpoint e verificar a propriedade do recurso, como o uid do cliente.

7. Frontend

A interface foi criada para permitir a demonstração das funcionalidades da API e inclui tela de login, listagem, cadastro, edição e exclusão de usuários, além da exibição das respostas recebidas.
